# SmartAttend

SmartAttend is an offline-first school attendance PWA built with Next.js 15, React 19, TypeScript, Tailwind CSS, and Supabase. Attendance can be recorded offline in IndexedDB and synchronized when a connection returns. AI-assisted identifications still require teacher verification.

## Configure Supabase

1. Create a Supabase project.
2. Open **SQL Editor**, paste and run [`supabase/migrations/20261127000000_initial_schema.sql`](supabase/migrations/20261127000000_initial_schema.sql). The app uses Row Level Security and accesses the database only from server routes with a server secret.
3. In Supabase project settings, copy the project URL and the server-side secret key. Set these in `.env` locally or in your hosting provider:

   ```env
   SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
   SUPABASE_SECRET_KEY=YOUR_SERVER_SIDE_SECRET_KEY
   AUTH_SECRET=YOUR_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
   ```

   For older Supabase projects, `SUPABASE_SERVICE_ROLE_KEY` is accepted in place of `SUPABASE_SECRET_KEY`. Never expose either key in browser code or use a `NEXT_PUBLIC_` prefix.

## Run locally

Install Node.js 22, then install dependencies and start the app:

```bash
npm install
npm run dev
```

The app opens at `http://localhost:3000`. Development mode supports sample sign-in without a Supabase connection. For actual persisted data, configure Supabase and run the SQL migration first.

To seed the sample classes, students, teachers, and two demo accounts, configure the Supabase environment and then run (PowerShell):

```powershell
$env:SEED_ADMIN_PASSWORD = "choose-a-strong-admin-password"
$env:SEED_TEACHER_PASSWORD = "choose-a-strong-teacher-password"
npm run db:seed
Remove-Item Env:SEED_ADMIN_PASSWORD, Env:SEED_TEACHER_PASSWORD
```

Sign in using `admin@smartattend.edu` or `priya.sharma@smartattend.edu` with the corresponding password. The other sample teacher accounts use the teacher seed password.

## Deploy to Vercel

Import the GitHub repository into Vercel, select the project root containing `package.json`, and use the Next.js defaults (`npm run build`; no output directory override). Add `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, and a random `AUTH_SECRET` in the Vercel project's Environment Variables for Production and Preview. Redeploy after setting variables. Apply the SQL migration in Supabase before signing in. Visit `/api/health` to check connectivity.

## Deploy to Render

The included `render.yaml` creates only the Next.js service; it uses the Supabase project you configure. Create the Blueprint, then add `SUPABASE_URL` and `SUPABASE_SECRET_KEY` to the Render service environment. `AUTH_SECRET` is generated by the Blueprint. Apply the same SQL migration to Supabase, then deploy. `/api/health` is configured as the Render health check.

## Useful commands

```bash
npm run dev
npm run build
npm start
npm run lint
npm run db:seed
```

Optional face-recognition integration can be configured with `FACE_RECOGNITION_API_URL` and `FACE_RECOGNITION_API_KEY`. Without them, the app uses its clearly labeled mock identification service.
